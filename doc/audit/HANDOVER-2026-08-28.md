### M-4 is ordering-sensitive — read this
The audit's original M-4 text was **wrong**: validity does *not* rebuild the member set from the
registration chain, it binds the channel-tree leaf's `member_pubkeys_root`, which §Q advances
in-circuit. The divergence (Manager's close-set vs the leaf) **already existed** because §Q blocks
were unproducible. M-2 narrowed it by making validity able to follow at all; what stays unenforced
is that the two advance **together**. Do not read M-2 as having introduced the problem.

## 3. Operational notes you will need

### Fixture regeneration (needed after ANY contract bytecode change)
`CloseLifecycleE2E` pins the manager's CREATE2 address, so any change to `IntmaxRollup.sol` or
`ChannelSettlementManager.sol` moves it and the close fixtures go stale. The failure names both
addresses; take the first one and:

```bash
WD_RECIPIENT=<new CREATE2 address> WD_OUT_PREFIX=close_ ./target/release/generate_withdrawal_fixture
```

~30 min, ~32 GB RSS. Do it **once**, after all contract changes for the batch have landed — not
per-branch, or you will pay for it repeatedly.

### EIP-170 budget is nearly spent
`IntmaxRollup` is **24,556 / 24,576 — 20 bytes of margin.** The next addition to that contract needs
a byte to come from somewhere. Precedent from this pass: `ETH_TOKEN_INDEX`'s public getter was made
`internal` after confirming no external consumer read it. **Never** shrink a guard to fit.

### Rust test discipline
The lib suite is OOM-killed at any parallelism — always `-- --test-threads=1`, and always a narrow
filter. Never run the whole lib suite casually (~32 GB, hours).

### Two test-integrity traps found the hard way
1. **`block.timestamp` is sunk past `vm.warp` under via-IR.** Two reads across a warp fold to a
   constant `0` delta while both report the later value. Any elapsed-time assertion must use
   `vm.getBlockTimestamp()`. One existing test was silently vacuous because of this.
2. **A test can reach the right revert for the wrong reason.** Every round-1 fraud test reached
   "fraud confirmed" through a revert in the verifier (the `catch`), never through a genuine
   `return false` — so the suite exercised only the fail-open path while reading as full coverage.

## 4. The practice that produced the results — keep it

Every fix in this pass was validated by **removing its own guard and observing the attack succeed**.
That is strictly stronger than "the tests pass", and it caught things review did not:

- Two agent deliverables arrived with a guard neutered by `if false &&` — including one fix's *own*
  guard. Report + green tests would have shipped a dead check.
- The M-1 circuit gate was only *believed* load-bearing until the circuit-only mutation showed both
  circuits proving a rotate-to-duplicate with every native mirror still enforcing.

**Before trusting any agent deliverable:** read the diff yourself, machine-sweep for disabled
patterns (`grep -rnE "if \(false|if false|// *STUB" contracts/src src`), and re-run the tests
yourself. Agent test results measured against a tree the agent was mid-mutation on are worthless,
and that happened here.

### The attack/defense loop earned its cost
Three rounds. Each round's *fixes* opened the next round's findings:

1. Round 1's C-3 fix (correct) made eras cyclable, turning `cancelClose`'s pre-existing lack of
   anti-replay from a one-shot accident into a **reusable censorship capability**.
2. Round 1's H-4 fix (correct) made the production fraud path **unsatisfiable** — the gate-8 shape
   (sound but non-functional), reintroduced by our own remediation.
3. Round 2's A1 and A3 guards, each sound alone, **composed into a permanent fund lock**: A1's floor
   consumed exactly the remedy A3's refusal relied on.

None of these is visible to a single audit pass. The structural lesson is in §5.

## 5. The invariant that now guards the class

Brick-class defects were reintroduced **three times** (C-3 → H-4 → A1×A3). The cause was structural:
four independent monotone latches gating a state machine whose only exits are `finalizeClose` and
`cancelClose`, with nothing asserting that at least one exit stays satisfiable.

`contracts/test/CloseExitLivenessInvariant.t.sol` now asserts exactly that, under a signed-state
**supply model** (versions exist only if some party co-signed them). It is non-vacuous by
exhibition: restore the round-2 refusal and the stateful fuzzer rediscovers the lock in ~19 s.

**If you add a fifth latch to the close lifecycle, that invariant is what tells you whether you just
bricked the channel.** Prefer adjusting an amount over refusing a transition — that is how A3 was
finally fixed (`finalizeClose` deducts the authorized burn instead of refusing, and now has no
version-dependent revert at all).
