## Layer K — a reference Keccak-256 (new module `Zkp.Implementation.Keccak256`)

Pure Lean specification of Keccak-256 as the EVM `KECCAK256` opcode and `keccak-hash` compute it:
Keccak-f[1600] (θ ρ π χ ι, 24 rounds, standard rotation offsets and round constants), sponge with
rate 1088 bits (136 bytes), the ORIGINAL Keccak padding `0x01 … 0x80` (NOT the SHA3 `0x06`),
little-endian 8-byte lanes, 32-byte output. Types: bytes are `List Nat` (< 256), lanes `Nat`
(< 2^64) using `&&&`, `|||`, `^^^`, `<<<`, `>>>`, `% 2^64`. `import Std` only.

API (fixed, other layers depend on it):

```lean
namespace Zkp.Implementation.Keccak256
def keccak256 : List Nat → List Nat            -- 32 bytes
theorem keccak256_length (m : List Nat) : (keccak256 m).length = 32
theorem keccak256_bytes_canonical (m : List Nat) : ∀ b ∈ keccak256 m, b < 256
def bytesToNat : List Nat → Nat                -- big-endian, first byte most significant
theorem bytes_to_nat_lt (bs : List Nat) (h : ∀ b ∈ bs, b < 256) : bytesToNat bs < 256 ^ bs.length
def digestU256 (m : List Nat) : Fin (2 ^ 256)  -- bytesToNat (keccak256 m), via the two lemmas
end Zkp.Implementation.Keccak256
```

Test vectors: `keccak256 [] = c5d2460186f7233c927e7db2dcc703c0e500b653ca82273b7bfad8045d85a470`,
`keccak256 "abc" = 4e03657aea45a94fc7d47ba826c8d667c0d1e6e33a64a036ec44f58fa12d6c45`, plus one
two-block vector (≥ 136 bytes) and one exactly-135-byte vector (single 0x81 pad byte), generated by an
independent pure-Python Keccak written by the agent and cross-checked against the two published
vectors above. Preferred: `theorem keccak256_empty_vector : keccak256 [] = [...] := by decide`
(try `set_option maxRecDepth 100000 in` and a generous `maxHeartbeats`; `decide` on a 100-step
bitwise loop hit maxRecDepth in a first probe, and `rfl` does not unfold — keep each attempt under
3 minutes). If no kernel-checked proof is achievable, the fallback is a BUILD-TIME executable
check: `#eval` of an `IO` action that throws on mismatch (so `lake build` fails), clearly labelled
as executed, not proved. Report which of the two landed.

Doc header must state: this is a reference specification of an external algorithm; it has no
in-repo source line; the in-circuit gadget is the external crate `plonky2_keccak` pinned in
`Cargo.lock` at `2507786148ae6323d0ea547bf88e1752f901434e` (git, branch wasm-main), which is
outside this audit's translation scope; the Solidity side is the EVM opcode.

## Layer D1 — signature bridge (new module `Zkp.Implementation.CloseSignatureBridge`)

Imports `CloseCircuit`, `FalconAggregate`, `FalconCore`. No edits to those three.

1. `toAggStatement : CloseCircuit.AggregateStatement → FalconAggregate.AggStatement`
   (`⟨s.message.words, s.signerCount, s.keys.map Words8.words⟩`) and
   `to_agg_statement_public_inputs : FalconAggregate.statementPublicInputs (toAggStatement s) = s.words`
   (both layouts are `message(8) ++ [count] ++ join keys`; `CloseCircuit.flattenAmounts` vs `List.join`).
2. The concrete meaning of an accepted aggregate. Define
   ```lean
   structure SignerEvidence (env : FalconAggregate.SigEnv) (authorized : List Nat → List Nat → Prop)
       (message : CloseCircuit.Words8) (keys : List CloseCircuit.Words8) (count : Nat) : Prop where
     witnesses : List FalconAggregate.SlotWitness
     count_eq : witnesses.length = count
     count_ge_one : 1 ≤ count
     count_le : count ≤ 8
     keys_eq : keys.map CloseCircuit.Words8.words =
       witnesses.map (fun w => env.pkDigest w.h) ++ List.replicate (8 - count) FalconAggregate.zeroSlot
     authorized_each : ∀ w ∈ witnesses, w.messageDigest = message.words ∧ authorized w.h message.words
   ```
   (or an equivalent ∃-form; a structure is preferred for readability).
3. The single-signature bridge. Determine the FAITHFUL concrete predicate in `FalconCore` that
   mirrors `gadget.rs` for one slot (`CircuitWitness`/`circuitNorm` — see
   `circuit_active_slot_implies_native_verify`, lines ~1520-1630) and define
   `FalconPredicateIsGadget (env : FalconAggregate.SigEnv) (e : FalconCore.HashEnvironment) (p : FalconCore.PolynomialProduct) : Prop`
   = "`env.falconAccepts h msg salt s2 = true` implies the FalconCore gadget/native predicate holds
   for the corresponding witness". Choose the conversion between `SlotWitness` fields (all
   `List Nat`, `messageDigest : Limbs`) and FalconCore's types (`SignatureParts`, `messageDigest : Nat`,
   `CircuitWitness`) so the statement is exactly what `gadget.rs`/`mod.rs` compute; document every
   conversion with the source line it mirrors. If the faithful choice needs a hypothesis (e.g. the
   message digest as a field element = `Words8` packed how `agg.rs` packs it), state that hypothesis
   explicitly and cite the line.
4. `FalconUnforgeable (e p authorized) : Prop` = "the FalconCore predicate holds for `(h, digest, sig)`
   ⇒ `authorized h digest`" (this is `LatticeHardness` in usable form).
5. Main theorem, no hypotheses beyond the three Props above and the tree:
   ```lean
   theorem accepted_aggregate_tree_gives_signer_evidence
     (env) (e) (p) (authorized)
     (predicate : FalconPredicateIsGadget env e p) (unforgeable : FalconUnforgeable e p authorized)
     (s : CloseCircuit.AggregateStatement) (t : FalconAggregate.AggTree)
     (hwidth : ∀ w ∈ FalconAggregate.activeWitnesses t, w.messageDigest.length = 8)
     (hok : FalconAggregate.evalTree env t FalconAggregate.aggLevels = .ok (toAggStatement s)) :
     SignerEvidence env authorized s.message s.keys s.signerCount
   ```
   via `FalconAggregate.agg_tree_ok_characterization` (gives `AggOk`) — `pks_eq` becomes `keys_eq`,
   `signed` + `predicate` + `unforgeable` give `authorized_each`. Note `AggOk.count_le : count ≤ 2^3`.
6. Non-vacuity: an explicit tree/env/statement with 2 signers for which the theorem's hypotheses hold
   (with `falconAccepts := fun _ _ _ _ => true`, `authorized := fun _ _ => True`).
7. Doc header: what is proved (the aggregate bookkeeping is now derived), what remains opaque and
   where each is now carried: recursive-verifier soundness (d0), aggregate statement lowering (d1),
   gadget faithfulness (d2), unforgeability (d3) — all to be TrustBoundary fields in layer T.
